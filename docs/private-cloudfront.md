# Using Private Objects Through CloudFront

You can configure this plugin to upload files with a non-public ACL, such as `private`. However, this only works if the files are served through a CDN URL and that CDN is correctly configured to fetch the objects from your bucket.

For Amazon CloudFront this means:

* your Joomla connection type must be **Amazon CloudFront**
* you must enter the CloudFront distribution URL in the plugin's **CDN URL** option
* your CloudFront distribution must use an **Origin Access Control (OAC)** for the S3 origin
* your S3 bucket policy must allow that specific CloudFront distribution to read objects from the bucket

If any of the above is missing, the URLs generated by Joomla will not work for objects uploaded with non-public ACLs.

## Example Setup

This is an example with fake data. Replace everything shown here with your own values.

### Example values

* Bucket name: `example-media`
* Bucket region: `eu-west-1`
* CloudFront distribution ID: `E1234567890ABC`
* CloudFront domain name: `d111111abcdef8.cloudfront.net`
* Joomla Media Manager root directory inside the bucket: `articles`
* OAC name: `example-media-oac`

### Step 1. Create the S3 bucket

Create an S3 bucket in your preferred region, for example `example-media` in `eu-west-1`.

You can keep the bucket private. In fact, that is the entire point of this setup.

### Step 2. Create the CloudFront distribution

Create a CloudFront distribution whose origin points to the bucket's **S3 REST endpoint**, not the website endpoint.

Correct:

```text
example-media.s3.eu-west-1.amazonaws.com
```

Wrong:

```text
example-media.s3-website-eu-west-1.amazonaws.com
```

The website endpoint cannot be used with OAC.

### Step 3. Create an Origin Access Control

Create an OAC for S3 origins and configure it with:

* Origin type: `s3`
* Signing behavior: `always`
* Signing protocol: `sigv4`

Attach the OAC to the S3 origin of your distribution.

If you are using the AWS CLI, the configuration file would look like this:

```json
{
  "Name": "example-media-oac",
  "Description": "OAC for example-media CloudFront distribution",
  "SigningProtocol": "sigv4",
  "SigningBehavior": "always",
  "OriginAccessControlOriginType": "s3"
}
```

### Step 4. Allow CloudFront to read from the bucket

Add a bucket policy which allows the CloudFront service principal to read objects, restricted to your distribution's ARN.

Example bucket policy:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCloudFrontServicePrincipalReadOnly",
      "Effect": "Allow",
      "Principal": {
        "Service": "cloudfront.amazonaws.com"
      },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::example-media/*",
      "Condition": {
        "StringEquals": {
          "AWS:SourceArn": "arn:aws:cloudfront::123456789012:distribution/E1234567890ABC"
        }
      }
    }
  ]
}
```

Make sure you replace:

* `example-media` with your bucket name
* `123456789012` with your AWS account ID
* `E1234567890ABC` with your CloudFront distribution ID

### Step 5. Wait for CloudFront deployment

CloudFront changes are not immediate. Wait until the distribution status becomes `Deployed` before testing.

### Step 6. Configure the plugin

Create or edit a connection in the plugin with these settings:

* Connection type: `Amazon CloudFront`
* Access Key / Secret Key: your normal S3 API credentials, or leave empty if you are using EC2 IAM role authentication
* CDN URL: `https://d111111abcdef8.cloudfront.net/articles`
* Bucket: `example-media`
* Region: `eu-west-1`
* Directory: `articles`
* Uploaded object ACL: `Private`

If your CloudFront distribution root maps directly to the bucket root, and you want Joomla to work in the bucket root, then your settings would instead be:

* CDN URL: `https://d111111abcdef8.cloudfront.net`
* Directory: leave empty

The **CDN URL** and **Directory** must correspond to each other exactly.

## How to Test

1. Upload a file through Joomla Media Manager using the connection configured above.
2. Confirm in S3 that the object ACL is the non-public ACL you selected.
3. Copy the URL inserted by Joomla into your browser.
4. Confirm the file is served through CloudFront.
5. Confirm that directly accessing the S3 object URL does not work anonymously.

If the CloudFront URL fails, check these items first:

* Are you using the S3 REST endpoint as the origin, not the website endpoint?
* Is the OAC attached to that origin?
* Does the bucket policy allow `cloudfront.amazonaws.com` with the exact distribution ARN?
* Has the CloudFront distribution finished deploying?
* Does the plugin's CDN URL match the distribution path and bucket directory?

## OAC vs OAI

CloudFront's older **Origin Access Identity (OAI)** mechanism may also work in some setups, but for new setups you should use **OAC**. This is what we recommend and what this documentation assumes.
